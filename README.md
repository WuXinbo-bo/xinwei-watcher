# Xinwei Course Watcher

Xinwei Course Watcher 是一个面向 [Beeline AI](https://www.beeline-ai.com/) 学习页面的 Chrome/Edge Manifest V3 扩展。它在课程学习页注入“课程监督助手”面板，读取左侧课程目录和页面上的学习进度，并按照设置的随机阈值自动切换到下一个未完成条目。

> 这是一个本地加载的辅助工具，不是 Beeline AI 官方扩展。请先确认你的账号、学校或平台规则允许使用自动化脚本，并自行承担账号和课程数据风险。

## 功能

- 扫描课程目录，识别媒体条目和部分文档条目。
- 显示已识别条目、章节、完成状态和未完成数量。
- 设置最小/最大观看阈值（默认 `81%`–`90%`）。每次切换会在区间内重新取一个随机值。
- 设置自动处理数量（默认 3 个）。
- 达到阈值后自动打开下一个未完成条目。
- 通过随机等待、滚动和鼠标事件模拟人工操作。
- 支持暂停、重新扫描目录、拖动和折叠悬浮面板。

## 安装

1. 下载或克隆本项目。
2. 打开 Chrome 的 `chrome://extensions/`，或 Edge 的 `edge://extensions/`。
3. 开启右上角的“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择本项目目录，例如：

   ```text
   D:\自动化脚本\xinwei-course-watcher-extension
   ```

6. 打开或刷新 Beeline AI 学习页面。修改代码后，需要在扩展管理页点击“重新加载”，然后刷新学习页面。

当前清单的匹配范围是：

- `https://www.beeline-ai.com/student/*`
- `https://www.beeline-ai.com/*`

实际使用通常应在类似下面的课程学习地址中进行：

```text
https://www.beeline-ai.com/student/#/courseInfo/learn/courseWare/...
```

## 使用方法

1. 登录 Beeline AI，并进入课程学习页面。
2. 等待左侧课程目录和播放器加载完成。
3. 点击面板中的“扫描目录”。先确认“学习目录”中能看到条目，且“未完成 / 总数”数量合理。
4. 设置参数：
   - **最小阈值 / 最大阈值**：触发切换的观看进度范围，取值应在 `0.50`–`0.99` 之间，例如 `0.81` 和 `0.90`。
   - **自动完成数量**：本次运行最多自动处理多少个条目。
   - **自动继续**：勾选后达到阈值会自动切换；取消后达到阈值会暂停。
5. 点击“开始监督”。面板会显示当前进度、随机阈值、已处理数量和日志。
6. 需要停止时点击“暂停”。如果课程目录是异步加载的，先手动点击“扫描目录”再开始。

### 推荐操作顺序

先只扫描并核对目录，再开始监督。首次使用建议把自动完成数量设为 `1`，观察一次切换是否正确，再增加数量。

## 工作原理

扩展不调用后台服务，也不发送网络请求。`content.js` 在页面空闲时运行，主要通过以下方式工作：

1. 从课程目录的 DOM 节点和图标 class 中推断条目、媒体类型及完成状态。
2. 从页面文本中寻找类似“已观看 85%”的进度文本。
3. 达到随机阈值后，模拟点击下一个未完成条目。
4. 对文档条目按固定随机时长停留，对媒体条目等待播放器切换后继续轮询。

目录 class、完成状态图标或进度文案改变时，识别可能失效。

## 已知问题与风险

以下问题来自当前代码审查，部分问题需要在真实课程页面验证：

### 高优先级

- **页面结构强耦合**：目录、状态和进度依赖大量固定 CSS selector 及“已观看 xx%”文案。平台改版后可能扫描为 0、把章节当条目，或无法触发切换。
- **进度可能取错元素**：`parseProgressText()` 会回退到整个 `document.body`，页面同时存在多个播放器、隐藏播放器或旧进度文本时，可能读取错误进度。
- **播放器切换判断不可靠**：`waitForMediaSwitch()` 把媒体 `currentTime >= 0` 视为已切换条件；播放器只要已初始化就可能提前返回，导致阈值基于旧页面继续运行。
- **一次操作可能触发两次点击**：`humanClick()` 先派发 `click` 事件，又调用 `el.click()`，部分页面可能因此重复打开条目或重复触发路由切换。
- **失败也会计数**：切换前就增加 `watchedCount` 和 `visitedKeys`。点击失败、加载超时或识别错误时，本次条目仍可能被算作已处理。

### 中优先级

- **动态目录需要手动重扫**：扩展只在注入和点击“扫描目录”时读取目录，没有 MutationObserver 或路由变化监听。异步加载、展开章节或 SPA 切换课程后，列表可能过期。
- **停止存在异步竞态**：暂停只能清理轮询定时器；已经进入 `advanceToNext()` 的异步流程仍可能在暂停后完成点击、等待并写入日志。
- **完成状态识别有限**：只有命中特定 `unStart` / `inProgress` 图标时才认为未完成。平台改名、使用文本状态或只显示百分比时，未完成数量可能为 0。
- **文档/媒体分类可能误判**：分类主要依赖标题关键词和时长文本，名称中包含“资料”“video”等词时可能被分到错误类型。
- **扩展范围偏宽**：`https://www.beeline-ai.com/*` 会在站点其他页面也注入脚本，增加冲突和性能影响；可按实际课程路由收窄 `matches`。
- **扩展图标没有功能**：清单声明了 action，但没有 popup 或点击监听；点击工具栏图标不会打开设置面板。

### 低优先级和维护问题

- 没有自动化测试、构建流程或版本发布流程，目前只能手动加载和手动回归。
- 设置不会保存，刷新页面后恢复默认值。
- `content.js` 内包含未使用参数/变量（例如鼠标移动中的部分临时坐标），增加维护成本。
- 模拟鼠标、滚动和自动观看行为可能触发平台风控，也可能违反平台使用条款。

## 排查方法

- 面板没有出现：确认当前 URL 命中 `manifest.json` 的 `matches`，并在扩展页点击“重新加载”后刷新页面。
- 扫描为 0：等待目录完全加载并展开章节，点击“扫描目录”；然后打开开发者工具 Console 查看脚本日志。
- 进度显示“未识别”：检查页面是否真的显示“已观看 xx%”。如果平台使用进度条属性或其他文案，需要修改 `parseProgressText()`。
- 自动切换错误：先把自动完成数量设为 `1`，关闭“自动继续”，手动观察目录识别和播放器切换，再调整 selector 或等待逻辑。
