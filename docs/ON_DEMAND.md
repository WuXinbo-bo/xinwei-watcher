# 1.3.1 首页课程卡片与单课学习流程

本版本在 test2 上将公开入口改为半自动操作。原有仿真鼠标轨迹、悬停、按下/抬起和最终点击，以及课内播放目标、短时长优先和有界恢复机制保持原有规则。

## 操作顺序

1. 点击「获取课程列表」：仅通过网站课表入口读取所有分页中正在上的课程，读取完成后停止。
2. 扫描结束后，首页直接显示「已发现 N 门课程」及逐课卡片，列表在固定高度内滚动，无需再进入全部课程页面。
3. 点击一张卡片的「开始学习」：只进入这门课，展开并核对完整目录，成功保存音视频、章节及页面完成标记后，自动开始本课待完成音视频。本课首轮结束后仍按原有规则刷新核对、有限重试，收尾后等待用户选择下一门。
4. 完整扫描后，当前课程的「音视频已确认」抽屉在对应卡片内展开，其他课程默认收起；扫描中隐藏，手动收起后进度更新不会强制展开。抽屉保留完成比例、待完成项数和只读明细入口，开合不影响任务。
5. 点击课程标题可只读查看详情；详情内的「扫描目录」只统计，不播放。暂停中的当前课程显示「继续学习」，其他课程在任务运行时不能同时启动。

列表中的未知数量不计作零或已完成；历史数量标为上次记录。每次「开始学习」先重新核对完整目录，扫描失败或暂停不进入播放。没有音视频的课程仅表示没有可处理媒体，不表示文档、考试、作业或整门课程考核已经完成。

## 记录与恢复边界

- 每次显式选择均建立新的操作代数，拒绝重复选择、迟到结果和其他课程的操作。扫描转入播放时再次隔离操作代数；转交期间到达的暂停请求仍会生效。
- 扫描先写草稿，完整结果成功提交后才替换上次目录。失败或暂停保留上次完整结果和时间。
- 更新课表后，历史目录仅作参考。首页标题不能当作课程及教学班的真实 ID，需经网站课程入口重新核对。
- 用户刷新页面需要显式继续；扩展自身核对刷新只授权相同标签、课程和操作代数的一次接回，并有过期时间。
- 旧版自动任务在更新时暂停并保留记录；通过「获取课程列表」进入新流程。
- 保存失败时禁止继续导航。暂停、重置和关闭页面沿用原有停止确认及恢复限制。

## 验证范围

- 按需协议测试覆盖列表结束等待、单课授权、完整扫描后转入播放、迟到结果、暂停与转交竞态、失败保留缓存、刷新与重启、单课播放结束停止、更新课表身份失效和保存失败禁止导航。
- 公开 UI 集成通过首页卡片逐课一键开始，验证音视频正常推进、故障恢复、网站完成标记、无媒体课程以及不自动跨课。媒体推进由合成网站执行，扩展没有写播放时间或伪造完成。
- Chrome for Testing 实际加载扩展的合成页面验收覆盖 19 类既有状态、新版首页卡片、运行锁定、暂停继续、长标题、窄屏、设置与内页、深色、减少动态效果、拖动与键盘。
- 运行检查命令、测试限制见 [tests/README.md](../tests/README.md)。真实页面的恢复操作按用户本轮明确要求执行，具体结果另记。

1.3.1 进一步压缩运行状态的重复标题和说明，将扫描时间折叠到「扫描信息」，增加只读的「全部／待完成」筛选并优先展示当前章节。课表与学习页的总进度统一使用已保存记录；「前往学习标签页」只切换并聚焦已有标签，不改变播放授权或任务记录。

本轮验证结果及真实页面恢复情况见 [UI_POLISH_1.3.1.md](UI_POLISH_1.3.1.md)。

合成测试和界面验收不能代替平台上的整门课程实测，也不证明登录、弹窗权限或平台完成计数始终可用。课程列表只读取网站标识为正在上的课程；具体考核要求仍以平台为准。
