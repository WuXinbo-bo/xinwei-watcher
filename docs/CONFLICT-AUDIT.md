# 逻辑冲突与竞态审查

审查对象：当前 HEAD `a373081`，只依据本地源码、历史验证记录和合成测试；本轮没有登录真实课程账号，也没有重新执行真实课程任务。本文区分“有显式防线的设计冲突”和“仍需验证的风险”，不把风险写成已复现缺陷。

## 高风险边界

| 边界 | 可能冲突 | 当前防线 | 剩余风险 / 验证 |
|---|---|---|---|
| 目录 DOM 与就绪判断 | 网站已渲染章节，但 DOM class 与旧 selector 不同；被误判为空目录并超时 | `a373081` 支持 `.section-content`，过滤隐藏响应式副本；相关 `media.test.cjs` Beeline fixture | 页面模板变体、部分章节延迟、真正空章节与未加载章节的区分仍需 fixture 和真实页数据 |
| 页面完成标记 vs 自然播放结束 | 页面先显示 80%/完成标记，若提前返回会留下未播放区间或错误标完成 | 播放记录分开保存 `ended`、`confirmed`、`progressGap`；课程末核对与单遍策略分开 | 平台标记语义若改版，selector/延迟窗口须重新核对 |
| content vs background 状态 | 消息往返、存储和广播期间用户暂停/重置；迟到成功可能继续点击 | runId/generation/owner 校验、`pendingCancellations`、`cancellationFence`、`resetEpoch`、保存后复查 | 极端 service-worker/浏览器关闭时只能依赖持久化和显式重新开始，不能由 jsdom 完全证明 |
| SPA 路由 vs sender URL | content sender 仍带旧 URL，而标签地址已变化；旧资源或旧文档可能接管 | 后台读取 `chrome.tabs.get()` 实际标签 URL；对 documentRouteKey、activeResourceKey 和新实例握手进行比对 | 依赖 Beeline SPA 对 route/hash 的实际约定；新路由模式需 fixture |
| 资源身份 vs 同名资源 | 同标题/重复标题、参数乱序或路由误变化可能错绑断点 | 课程 key + 目录 key + 精确 routeKey；不同 query key 可排序，但保留值、重复 key、编码 key 的严格性 | 网站 URL 规则若改变需要再次验证；不要把宽松匹配扩大 |
| 中断恢复 vs 用户操作 | 恢复等待期间点击暂停、出现验证码、登录失效或跳到其他页 | 同一 interruption episode 有次数上限；页面阻断先于导航；未确认 URL 不强行拉回 | 现有 `interruption-integration` 有一次历史观察超时记录，应持续关注其稳定性 |
| 自动播放 vs 目录检查 | 刷新/统计时网站播放器晚到自动播放，与“先核目录后只放行目标资源”冲突 | MutationObserver + 媒体事件早期观察；暂停授权按 generation 绑定；测试覆盖晚到媒体 | 各媒体框架/Shadow DOM/跨域 iframe 可能不在观察范围，当前 manifest 也不注入 iframe |
| 统计页与播放页标签 | 统计页迟迟不关或导航失败，首页可能提前开始下一个课程，形成两个 worker | home/worker/returning tab 分离；关闭前核验身份；return deadline 持久化退避 | 浏览器关闭标签、权限或 API 失败时任务等待/停止属于预期但需说明 |
| UI 收起 vs 任务控制 | 隐藏面板如果误调用 pause 会中断正在执行任务 | `setPanelExpanded()` 仅变更可见性/位置/控件显示；UI 专项测试断言 running 不变 | 真实长任务期间只需一次浏览器回归确认隐藏 DOM 不改变执行器 |
| UI 关闭 vs 日志同步 | 面板隐藏时日志更新/后台同步停止，或重开重复计数 | 后台任务同步独立定时器；日志按 stable id 合并，最多 80 条可见/待同步日志 | DOM 被宿主脚本删除后是否自动重建未有覆盖 |
| 推广 SVG vs 面板交互 | SVG 覆盖课程按钮，或者点击文本区域误触面板/链接 | promotion 容器 pointer-events none，仅绘制文字可命中；关闭和移动端退化有 UI 测试 | SVG 字形 hit testing 受浏览器实现影响；隔离 Edge 测试有记录，其他 Chromium 版本未验证 |
| 浏览器/扩展重启 vs 自动续播 | 持久化 running 状态被当成播放授权 | 从磁盘加载强制 `running=false`，改为 `interrupted`，必须用户显式开始 | 意外关机前的播放位置是保守提示，不保证平台位置可恢复 |

## 状态/证据容易混淆的地方

以下是代码概念不同而 UI 文案可能相近的边界，维护时应保留区分：

- `remaining === 0` 不一定表示课程可完成：可能还有“已开始未结束”“已结束未确认”“错误”“缺口”记录。
- 页面 `confirmed` 不等于本次任务 `ended`；80% 页面完成目标也不等于播放器自然结束。
- `phase === course` 不代表一定在播放：可能处于目录核对、课程末校验、恢复等待或课程刷新接管。
- `phase === paused/manual/interrupted` 不能靠页面 `hello` 自动变成运行；必须由显式用户动作授予新 generation。
- 首页任务摘要、页面考核点数字和课程目录统计是不同数据源，不应互相覆盖或充当完成证据。
- “资源恢复次数”“单资源重试数”“课程刷新次数”“跨课程退避次数”是不同预算，合并会造成重复扣次或预算被迟到消息清零。

## 当前可见风险

1. **目录覆盖仍是平台 DOM 耦合**：近期已修复真实根因，但 selector 与 Beeline 页面组件结构直接绑定。应优先维护脱敏 HTML fixture，分别覆盖目录未载入、折叠、真实空章节、隐藏副本、叶项晚到。
2. **集成超时的历史信号**：`docs/VERIFICATION.md` 记有隔离浏览器并行运行时出现过长测试观察超时，关闭浏览器后后续完整复跑通过。不同历史运行记录的总数口径不同；本轮当前 HEAD 复跑为 387/387。它说明负载敏感性值得关注，不证明测试无效或业务一定有 bug。
3. **长时间与睡眠恢复**：合成测试可控制 timers 和消息时序，却不能验证浏览器睡眠、操作系统省电、网络断开及真实平台迟到标记组合。
4. **安全阻断可用性**：登录、验证码、题目/平台限制按人工处理停止，这是边界策略，不应通过“增强自动恢复”绕过。
5. **跨浏览器差异**：Edge 有 UI/本地 fixture 验证记录；未据此推断所有 Chrome/Edge 版本、缩放、触屏或宿主页面 CSS 组合均已覆盖。

## 建议排障取证顺序

发生“目录统计失败”时，先保存页面路由和脱敏 DOM 结构/节点计数；随后核验活动目录 root、可见性、章节展开、真实叶项 selector、稳定等待条件。只有目录快照正确生成后，才检查后台 `directory-checkpoint` 的校验结果；最后才追播放恢复、重试和课程切换。不要将保护性停止或超时后的恢复路径当成最初根因。
